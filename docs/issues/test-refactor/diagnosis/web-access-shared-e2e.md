## 2. 반복 패턴 상위 3개와 우선순위

### 패턴 1. 우리 DB와 내부 모듈을 mock 해서 핵심 로직이 한 번도 실행되지 않는다 ([M3][M8])

- 해당: project-name-queries, project-revocation-actions, project-session L103-114, require-access, verify-access, rate-limit/index, storage-limit-integration, project-routing (8개 파일).
- 가장 큰 구멍은 레이트리밋이다. 잠금 규칙(만료 리셋, sliding 연장, 잠금 뒤 미연장)은 전부 SQL(`src/shared/lib/rate-limit/index.ts:48-63`)에 있다. 그런데 유닛은 DB 반환값을 stub 하고(`index.test.ts:32`), 잠금을 검증한다는 두 테스트(`verify-access.test.ts:69-95`, `project-revocation-actions.test.ts:98-112`)는 `src/shared/test/__mocks__/rate-limit.ts:8-26` 의 JS 재구현을 검증한다. SQL 이 틀려도 스위트는 초록이다.
- 전역 `setup-tests.ts:8-16` 이 `requireProjectAccess`, `checkStorageLimit` 을 항상 통과로 고정한다. 그 결과 "액션이 용량 초과 시 거부" 같은 교차 관심사가 어디서도 검증되지 않는다.
- 우선순위 1 (보안). `rate_limit_buckets`·`projects` 실 DB 통합 하네스(로컬/테스트 스키마)를 먼저 만들고 verify-access, revocation, rate-limit 을 그 위로 옮긴다. 하네스가 생기면 project-name-queries, project-session L103-114 도 이동한다.

### 패턴 2. E2E 가 scenario.md 의 Then 을 단언하지 않거나 항상 참인 단언을 쓴다 ([M9][M8])

- 빈 POM 단언 `expectProjectName`(project-dashboard.page.ts:82)이 실행 중인 스펙(project-access.spec.ts:21)에서 호출된다.
- 0 바이트 `departure.spec.ts` 가 수집된다.
- 케이스 취소 테스트의 부재 단언은 페이지네이션 때문에 항상 참이다(create-testcase.spec.ts:208 + page.ts:132-135).
- 미검증 Then: 폼 닫힘(testcase), Step1 인라인 에러(project), 대시보드 도달(project-search).
- 낡은 fixme·문서: rate-limit 인메모리 서술, suite 실패 fixme, scenario.md 의 `scenario/cases` 경로, README `.e2e.ts`.
- 우선순위 2. 블로킹 항목이라 수정 비용이 작고(POM 메서드 1개, 파일 1개 삭제, 단언 몇 줄) 효과는 즉시 난다. 1절 상단 블로킹 1~4를 한 PR 로 묶는 것을 권한다.

### 패턴 3. 같은 동작을 여러 레이어·파일에서 중복 검증하고, 미사용 코드와 타입까지 테스트한다 ([M4])

- E2E 중복: 레거시 `create-project/*` 가 `scenario/project` 와, `scenario/access` 골든패스·틀린 식별번호가 `smoke/access` 와 겹친다. 레거시 폴더는 POM 규약(AGENTS "테스트 아키텍처")도 따르지 않는다. 결과는 매 실행 프로젝트 row 2개 생성과 ③ 저하다.
- 유닛 중복·무가치: access-token parse 중복, access-policy 싱글톤·타입 리터럴 검증, password-hash 의 bcryptjs 동작 재확인과 미사용 sync API, 미사용 `getTokenRemainingTime`, example.test.tsx.
- 우선순위 3. 삭제 15행 대부분이 여기에 속하고, 대체 검증이 이미 있음을 1절에 적었다. 미사용 코드(`hashPasswordSync`, `verifyPasswordSync`, `getTokenRemainingTime`)는 코드 제거와 같이 처리한다.
