# 테스트 진단 G1: apps/web/src/entities, features

- 기준: `docs/issues/test-refactor/methodology.md` [M1]~[M9], 절차: `.claude/skills/diagnose-test/SKILL.md`
- 대상: 테스트 56개 파일 (entities 29, features 27). 모든 테스트 파일과 대상 소스, 공용 목(`shared/test/__mocks__/db.ts`, `setup-tests.ts`)을 읽고 판단했다. 테스트는 실행하지 않았다.
- 경로는 `apps/web/src/` 기준. `L23` 은 테스트 파일 줄 번호(소스 줄이면 "소스 L" 로 표기).
- 평가: ① 회귀 방지 ② 리팩터링 내성 ③ 빠른 피드백 ④ 유지보수성, O / △ / X.
- 처분 규칙
  - `set()`/`values()` 인자 단언은 [M3] 위반(managed DB 와의 통신 단언)이지만, 그 액션 고유의 변환(정규화, 날짜 병합, 섹션 재결정 등)을 검증하는 유일한 수단이면 "유지(통합 전환 대상)" 로 둔다. 입력을 그대로 넘기는지만 보는 경우는 C 분류로 삭제한다.
  - "레이어 이동" 중 DB 통합으로 가는 항목은 저장소에 DB 통합 테스트 인프라가 아직 없다(`pglite`/`testcontainers`/테스트 DB 설정 없음). 인프라가 생기기 전까지는 현 테스트를 지우지 말고 둔다.
  - `catch` 에서 고정 메시지를 돌려주는지만 보는 "DB 에러 시 에러를 반환한다" 류는 [M4] C 분류로 삭제한다. 이 동작은 다른 곳에서도 검증되지 않지만, 검증할 가치가 없는 코드다.
  - 헛검증은 실행으로 확인하지 않았으므로 "의심" 으로만 적는다.
