# 세션 만료·폐기 보완 (#314)

## 동작 변경

- web 로그인과 프로젝트 생성은 검증한 비밀번호 해시를 서버 키로 HMAC 처리한 버전을 토큰에 넣는다. 해시 원문은 쿠키에 포함하지 않는다.
- 액션의 프로젝트 가드와 접근 페이지 정책은 서명·시간 검증 후 현재 DB의 비밀번호 버전과 ACTIVE 상태를 확인한다. 비밀번호 변경, 프로젝트 삭제·보관, 누락 리소스, DB 장애는 이전 세션으로 통과할 수 없다.
- 기존 버전 정보가 없는 토큰은 재로그인이 필요하다. 비밀번호를 변경한 브라우저도 재인증해야 한다.
- 백오피스는 공유키 원문 대신 256비트 난수 쿠키를 발급한다. DB에는 SHA-256, 공유키 버전, 만료 시각만 저장한다.
- 관리자 페이지와 공지 액션은 DB 세션을 확인한다. 8시간 만료 경계부터 거부하며 로그아웃·재로그인은 해당 세션을 DB에서 제거한다. 다른 세션에는 영향을 주지 않는다. 공유키 교체는 이전 공유키 버전 세션을 거부한다.
- 로그인 시 세션 저장이 실패하면 쿠키를 발급하지 않는다. 로그아웃 시 DB 삭제가 실패하면 성공 리다이렉트를 수행하지 않는다.

프로젝트 토큰은 비밀번호 변경에 따른 전체 폐기이며 개별 브라우저 로그아웃은 기존 쿠키 삭제 방식이다. web의 개별 세션 폐기 저장소 도입은 이번 범위에 포함하지 않는다. 관리자 개별 세션 폐기는 이번 변경에 포함된다.

## 배포 순서

1. 대상 DB와 서버 연결 역할을 확인하고 `0021_admin_sessions.sql`을 먼저 적용한다. 실제 적용은 이 코드 작업에서 수행하지 않았다.
2. `admin_sessions`의 RLS 활성화·강제 및 anon/authenticated deny 정책, 서버 역할의 필요한 SELECT/INSERT/DELETE 권한을 확인한다. 운영 정책 적용 여부는 로컬 파일 검증과 구분한다.
3. web과 백오피스의 새 버전을 배포한다. 기존 쿠키는 재로그인해야 한다. 구버전/신버전 인스턴스를 오래 혼용하지 않는다.
4. 합성 계정/프로젝트로 정상 로그인, 비밀번호 변경 후 이전 쿠키 거부, 관리자 로그아웃 후 재전송 거부, 공지 변경 가드를 확인한다.

환경 변수나 키를 추가하지 않는다. 관리자 세션 테이블이 없거나 접근할 수 없으면 인증은 거부된다. 구버전으로 롤백하면 과거 검증 방식이 복구되므로 세션 폐기 보장이 유지되지 않는다는 점을 배포 판단에 반영해야 한다.

만료 행은 권한을 부여하지 않지만 자동 정리하지 않는다. 운영 보관 정책에 따라 `expires_at` 인덱스를 이용한 주기적 정리를 별도 설정할 수 있다.

## 검증과 한계

- web 인증·프로젝트 생성·실행 보안: 8개 파일, 103개 테스트 통과.
- 백오피스 전체 단위 테스트: 7개 파일, 31개 테스트 통과.
- DB 패키지 단위 테스트: 2개 파일, 10개 테스트 통과.
- 새 보안 테스트는 실제 토큰 서명, 페이지/액션 가드, 비밀번호 변경·삭제 액션과 관리자 로그인/로그아웃·공지 액션을 실행하며 DB·외부 서비스만 모킹한다.
- 백오피스 타입 검사 통과. web 전체 타입 검사는 기존 AI/Zod/폼 관련 오류가 남아 실패했으며 이번 변경 파일에서는 진단이 없었다.
- 로컬 Node 22.13.0과 기존 설치 의존성을 재사용했다. 작업 트리의 DB 스키마를 보도록 임시 Vitest/TypeScript 경로 매핑을 사용했다. CI의 Node 20 및 lockfile 재설치 검증은 별도다.
- 실제 DB 마이그레이션, 운영 쿠키 재전송, 전체 앱 빌드 및 브라우저 E2E는 수행하지 않았다.

클로드의 개발 작업과 분리된 보안 작업 트리에서 작성했다. 기존 사용자 수정과 다른 작업 트리는 변경하지 않았다.
